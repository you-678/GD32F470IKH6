## 同日再追加：落地非阻塞状态机教学示例（用户学面试模板，选「我这个项目具体怎么改」）
- 用户贴了一套「句柄 + start + process + 任务数组」非阻塞模板，反复表示没听懂；定位到卡点是"具体到我的工程怎么改"→ **直接在工程里做出可运行最小示例**，不再讲道理。
- **关键前提**：本工程原本没有 `uwTick`，只有阻塞式 `delay_1ms()`（`systick.c` 里 `volatile delay` 忙等）。所以先补地基：`systick.c/.h` 加 `volatile uint32_t uwTick` + `get_tick()`，`delay_decrement()` 里 `uwTick++`（每 1ms，兼保留旧 delay）。默认 TRNG main 原本**没调 systick_config()**，已在 main 里补上。
- 新增 6 个文件（全在 App/，已加入 uvprojx 的 App 组）：
  - `app_scheduler.c/.h`：任务数组 `task_list[]` + `task_scheduler()`；process 用 extern 声明；按键排前（响应优先）；事件型 `app_usart_task()` 不进数组。
  - `app_nb_led.c/.h`：类型 A 状态机流水灯，`nb_led_start(ms)` + `nb_led_process()`，`state` 记 0/1/2 轮流亮，"到点记 tick=now"而非 `+=interval`。
  - `app_nb_key.c/.h`：类型 B 周期扫描（5ms），边沿检测消抖 + `pressed` 标志替代 `while` 死等松手；PA0 默认上拉、按下=0（`KEY_TRIG_FALLING_PULLUP`）。
- `main.c`（GBK 编码！用 Python 按 GBK 读改写，避免乱码）：include 4 个新头 → 串口初始化后加 `systick_config()`+3×`bsp_led_init`+`bsp_key_init(KEY_WAKEUP,KEY_MODE_GPIO)`+`nb_led_start(500)`+`nb_key_start(5)` → while 里加 `task_scheduler()`（TRNG、`app_usart_task()` 全部保留）。
- **编译验证**：Keil UV4 单实例问题依旧（见上条），改用 `arm-none-eabi-gcc -fsyntax-only -DGD32F470`（器件宏由 DFP 注入，命令行要手动补；`-IComponents/drivers/OV2640` 也要补）→ 5 个改动文件全部 PASS。GBK 的 main.c 需先转 UTF-8 暂存到工程目录内再编（Windows GCC 解析不了 Git Bash 的 `/tmp`）。
